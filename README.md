# COURTIVE Daily Brief 카드 생성기

피그마 `02 · Instagram & Daily Brief` 페이지의 `C · Daily Brief` 컴포넌트를 그대로 옮긴 1080×1350 카드 렌더러.

## 사용법

```
pip install playwright jinja2 pillow --break-system-packages
python3 -m playwright install chromium
python3 render.py data/2026-10-24.json
```

결과는 `out/<파일명>/`에 저장된다.

- `01-cover.png` … 카드별 PNG (인스타 업로드용, 1080×1350)
- `contact-sheet.png` 검수용 한눈에 보기
- `report.json` 카드 구성, 글자 크기를 줄인 슬롯, 넘친 슬롯 목록
- 넘친 슬롯이 하나라도 있으면 종료 코드 1로 실패한다 (발행 금지 신호)

## 피그마 규칙 → 코드

| 규칙 (피그마 20·21장) | 구현 |
|---|---|
| 1–4경기 160px 행 · 가운데 정렬 | `games.sparse` |
| 5–8경기 94px 행 · 한 장 | `games.dense` |
| 9–15경기 94px 행 · 2장, ceil(n÷2) + floor(n÷2) | `build_cards()` |
| 경기 없는 날 → 표지 + 뉴스 + 순위 + 마무리 | `games: []` |
| 원정 왼쪽 · 홈 오른쪽, 승자 W + 블루(스트립은 시안) | `prep_game()` |
| 접전 5점 차 이내 · 연장 · 대역전 20점 이상 | `game_type()` (우선순위 연장 > 대역전 > 접전 > 일반) |
| 사진·PHOTO 레이어 없음 | 템플릿에 이미지 슬롯 없음 |

## 글자 수 제한

`schema.json`의 `maxLength`가 권장 상한이고, 실제 판정은 브라우저에서 줄 수와 가로 넘침을 재서 한다.

| 슬롯 | 크기 · 줄 | 권장 상한 | 넘칠 때 |
|---|---|---|---|
| 표지 헤드라인 | 96px · 2줄 | 20자 | 84 → 72px, 그래도 넘치면 실패 |
| 경기 헤드라인 | 68px · 최대 2줄 | 28자 (1줄 14자 권장) | 실패 |
| 경기 라벨 | 26px · 1줄 | 18자 | 실패 |
| 선수 이름 | 32px · 1줄 | 12자 | 28 → 26px |
| 뉴스 제목 | 88px · 3줄 | 33자 | 80 → 72px |
| 뉴스 본문 | 36px · 3줄 | 72자 | 실패 |
| 확인 문구 | 26px · 1줄 | 29자 | 실패 · 비우면 숨김 |
| 마무리 제목 | 96px · 2줄 | 20자 | 실패 |
| 푸터 출처 | 21px · 1줄 | 22자 | 실패 |
| 푸터 안내 문구 | 21px · 1줄 | 38자 | 실제 발행은 빈 값 |

## 팀 컬러 시스템 (피그마 22장 · E · Team Color System)

- `teams.json`: 30개 구단 한글명과 주·보조·3차 컬러. 피그마 변수 컬렉션 `COURTIVE / Team Colors`(Team/ABBR/Primary…)와 같은 값.
- 팀은 팀 로고로 표시한다. 피그마 컴포넌트 `Team Logo/약어`(F · Team Logos, NBA 공식 SVG 원본)를 쓰고 비율·색은 바꾸지 않는다.
- 쓰는 곳: 스코어 행 양끝 8px 바, 스코어 스트립 상단 10px 밴드, 득점자 약어 앞 6px 바, 순위 행 왼쪽 6px 바, 뉴스 팀 태그(`news[].teams`).
- 배경과 구분이 안 되면 `accent()`가 보조 → 3차 컬러로 자동 교체한다 (대비 1.8:1 이상, 또는 색차 ΔE 45 이상).
- UTA는 2025-26 리브랜딩 공식 HEX를 확인하지 못해 근사값(`verified: false`)이다. 확인되면 `teams.json`과 피그마 변수만 바꾸면 된다.

## v2 템플릿 (기본값, `templates/card_v2.html.j2`) — 2026.10.26 확정

- 발행 순서: 표지 → 게임 리포트(최대 3) → 뉴스 → 스코어보드 → 순위 → 마무리.

- 사진·로고 중심. 사진은 위를 꽉 채우고, 코티브 로고의 사선으로 잘린다. 게임 리포트의 사선 띠는 두 팀 컬러를 반씩 쓴다.
- v1로 그리려면 `--template card.html.j2`.
- 사진 필드: `photo`(데이터 파일 기준 상대 경로), `photo_credit`(필수), `photo_pos`(자를 위치, CSS object-position), `photo_zoom`(확대 배율). 표지·게임 리포트(`featured[]`)·뉴스에 쓸 수 있다.
- 사진이 없으면: 표지는 심벌, 게임 리포트는 사선만으로 그린다. 뉴스는 사진이 기본이라, 사진이 없으면 렌더를 실패로 막는다(정말 못 구했을 때만 `allow_logo_panel: true` → 관련 팀 로고 패널).
- 푸터는 사진 크레딧 한 줄만 쓴다(출처·시각·쪽 번호는 넣지 않음). 사진이 있는 카드에서는 라이선스 표시라서 지우지 않는다.

### 사진 원칙

- 출처와 라이선스가 분명한 사진만 쓴다. 지금은 위키미디어 공용의 CC BY / CC BY-SA 사진만 쓴다. 통신사(AP·Getty·Imagn)와 구단 갤러리 사진은 쓰지 않는다.
- 크레딧은 푸터 둘째 줄에 넣는다: 자료 사진(촬영 연월, 장소), 작가, 라이선스 / Wikimedia Commons.
- 경기 당일 사진이 아니면 반드시 "자료 사진"과 촬영 연월을 적는다.
- CC BY-SA 사진은 색을 바꾸지 않는다. 자르기와 아래쪽 그라데이션만 쓴다. 색을 바꾸면 변형본도 CC BY-SA로 공개해야 한다.
- 원본 정보는 `photos/<날짜>/src/credits.json`에 남긴다.

## 피그마 편집용 템플릿 (G 섹션)

v2 템플릿은 피그마 `G · Daily Brief v2 · 편집용 템플릿`에 컴포넌트로 그려져 있다. 피그마에서 고친 내용을 코드로 옮기는 방법과 레이어 ↔ CSS 대응표는 `figma/README.md`, 비교 스크립트는 `figma/snapshot.js`.

## 인스타그램 발행

- `render.py`는 카드마다 `jpg/NN-종류.jpg`(업로드용, 게시 API는 JPEG만 받음)와 `caption.txt`(요약·출처·사진 크레딧·해시태그)를 같이 만든다.
- 카드는 1080×1350(4:5). 캐러셀은 첫 장 비율로 모두 잘리므로 모든 장을 같은 크기로 둔다.
- 계정 세팅 키트(프로필 사진·하이라이트 커버)는 `instagram/kit.py` → `out/instagram-kit/`.
